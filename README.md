# LOL

Recherche, documentation et outillage autour du trading sur Pump.fun (Solana).

## Code

- **[analyse/figures-chartistes/](analyse/figures-chartistes/)** — Outil autonome (Python sans dépendance) qui mesure les **figures chartistes haussières les plus représentées parmi les tokens gradués** — hier, il y a 7 jours, il y a 30 jours — depuis la base de capture ClickHouse (recommandé), Moralis ou les API publiques ; 12 détecteurs (drapeau, fanion, triangle ascendant, biseau descendant, double/triple creux, ETEi, tasse, canal…) validés par autotest. Méthode et limites : [pumpfun-figures-chartistes.md](pumpfun-figures-chartistes.md).
- **[capture/](capture/)** — **Phases 1 et 2 en TypeScript** : capture en continu du programme Pump.fun via Triton Yellowstone gRPC vers ClickHouse (créations, trades, graduations, slots, transactions brutes rejouables, détection de trous, monitoring), plus l'outillage de phase 2 — labellisation des issues (`npm run labels` : token_summary + matrice token × minute × horizon) et réconciliation RPC des trous (`npm run reconcile`, avec mode `--verify` pour la DoD). Voir [capture/README.md](capture/README.md).
- **[pumpfun-guide-pas-a-pas.md](pumpfun-guide-pas-a-pas.md)** — **Runbook de déploiement** : les 12 étapes ordonnées du VPS OVH nu à la capture en service permanent (Triton, sécurisation, Node, ClickHouse, clone, .env, migration, premier lancement, systemd, surveillance 48 h, validation), avec vérifications et remèdes aux pannes courantes à chaque étape.

## Documentation

- **[pumpfun-figures-chartistes.md](pumpfun-figures-chartistes.md)** — Les figures chartistes haussières sur les tokens gradués : ce qu'on mesure (population, fenêtres hier/J-7/J-30, phase courbe vs post-graduation), définition opérationnelle des 12 figures détectées, mode d'emploi de l'outil, hypothèses mécaniques (pourquoi la continuation domine en phase courbe) et limites (subjectivité des seuils, biais du survivant, co-occurrences).
- **[pumpfun-donnees-strategie.md](pumpfun-donnees-strategie.md)** — Référentiel complet des données exploitables pour une stratégie d'achat/revente sur Pump.fun : métriques de base (prix, volume, holders…), métriques dérivées (net flow, vélocité d'inflow…) et features d'expert (profil du déployeur, détection de bundles/snipers, clusters de wallets, smart money, wash trading, exécution), avec les sources de données et les pièges de backtest.
- **[pumpfun-choix-strategie.md](pumpfun-choix-strategie.md)** — Comparatif des points d'entrée (sniping à la création, milieu de courbe, pré-graduation, post-graduation, suivi smart money, seuils de holders), choix des timeframes (bougies en secondes vs 5 min/15 min/1 h, durées de détention), arbre de décision et progression recommandée.
- **[pumpfun-trouver-un-edge.md](pumpfun-trouver-un-edge.md)** — Méthode de recherche d'edge pour un bot sous Triton (Yellowstone gRPC) : fondation de données, boucle hypothèse → étude d'événement → walk-forward → shadow → micro-réel, familles d'hypothèses classées par coût de falsification, modèle de coûts, courbe de décroissance du signal, architecture du bot et « usine à edges ».
- **[pumpfun-plan-execution.md](pumpfun-plan-execution.md)** — Plan d'exécution séquencé en 6 phases avec critères de sortie mesurables : capture gRPC → labels/backfill → bases propriétaires (devs, smart money) → trois études fondatrices → shadow bot → micro-réel, plus le choix de stack et la checklist de démarrage.
- **[pumpfun-webhook-vs-grpc.md](pumpfun-webhook-vs-grpc.md)** — Arbitrage webhooks vs Triton (Yellowstone gRPC) : latence, ordre, trous silencieux, débit, coût ; impact par phase du plan et par famille d'edge ; la recherche en temps-slot qui sauve un démarrage low-cost ; et le spectre complet webhook → WebSocket → gRPC partagé → gRPC dédié avec recommandation.
